# Blog, public lecture sheets and student AI

## First: use the updated source

This version is newer than `diction-production-progress.zip`. Back up your existing local project and database first. Copy or deploy this source using your own private `.env.local`; no credentials are included. Run `npm ci` using Node 22.13 or newer, then `npm run dev`. See `DASHBOARD-LOGIN.md` and `ATLAS-SETUP.md` for local database and admin setup. Set `NEXTAUTH_URL` and `AUTH_URL` to the exact origin used in the browser, such as `http://localhost:3000`, and restart the server after environment changes. Do not paste secrets into chat or screenshots.

## Blog

Admin → Content: choose Blog, enter a Bangla title and either Bangla article text or a supported image, YouTube video, or published lecture-sheet PDF, then save. See `ADMIN-ROLES-AND-CONTENT.md` for the multimedia workflow and role permissions. English and other optional information can be entered by expanding the optional section. If English is left blank, the Bangla title/article is stored as the English fallback. Check Published before saving to make the post appear on the public blog; otherwise it remains hidden. Create a proper English translation if you want distinct English text. The page title and description, canonical path and sitemap aid discovery but cannot guarantee search indexing or rankings. Configure your real HTTPS public origin and verify your domain in Google Search Console after launch. Never put personal or confidential information in public content.

The exact error in the earlier downloaded local installation was not supplied, so it is not proven that missing English fields were its only cause. In an isolated synthetic test the new browser form saved and published a Bangla-only article successfully, with English fallback. If your own install still fails, note the exact on-screen message and server error category, whether you're logged in as an active admin, whether MongoDB is reachable, and whether your canonical origin matches; redact any credentials and student data.

## Public lecture sheets

Admin → Public lecture sheets → provide Bangla title and a PDF of at most 4 MiB → Save draft → Publish. Class, subject, description and English details are optional, but useful for readers and search metadata. A public index is at `/bn/lecture-sheets` and `/en/lecture-sheets`; each published sheet has its own indexable page and an open/download link. No account is required to view published sheets. Withdraw hides the page and PDF immediately from the application; delete removes the record from the live database. Neither action recalls copies that people downloaded or that search engines, browsers, CDN caches or backups retained. These are separate from existing private batch materials.

Only admins can upload and change the sheets. Draft records and their bytes are not exposed by the public routes; an admin-only draft preview and a public-page PDF preview are available; a synthetic simple PDF was rendered in a local browser test; editing is not implemented, so delete and reupload a draft if corrections are needed. The admin list shows the most recent 200 items and the public list/sitemap the most recent 500; search/pagination and editing must be implemented before the library grows beyond these limits. The app stores PDF bytes in MongoDB, so monitor database storage/cost and plan backups, restore, deletion and limits. The upload checks size and the `%PDF-` signature; this is NOT complete PDF validation, malware scanning or sanitization and can be spoofed. Only publish trusted, rights-cleared files that an operator has checked with appropriate security tools. Avoid embedded active content. Do not upload student records, identifying details or confidential content. Review security and rights before real publication.

## Student AI

Student dashboard → AI Study Buddy, or `/bn/dashboard/study#ai-study-buddy`, requires an active student account linked to a student profile. The new public assistant is at `/bn/study-buddy`; see `PUBLIC-PRACTICE-AND-AI.md` for its additional flag. Admin status and a safe connection diagnostic are at Admin → AI Study Buddy. The feature intentionally defaults off. `AI-SETUP.md` explains local private key and model configuration, both required flags, restart, student test account, and the prerequisite guardian/privacy/provider/safety review. The broader data-collection flag affects other features too. A configuration checklist is not a live AI test. No live Gemini provider was tested here; never send keys in chat. AI responses may be wrong and students must not enter personal information.

## Verification and limitations

The current source passed `npm run typecheck`, `npm test`, `npm run build -- --webpack`, and the focused public-learning workflow test using synthetic data and a mock AI provider. See `PUBLIC-PRACTICE-AND-AI.md` for the test coverage and important production blockers. `npm run test:content-sheets` used an isolated temporary MongoDB, synthetic admin/data and Playwright against the production build: it checked Bangla-only browser blog save/publication and fallback; public-sheet authorization/origin, draft privacy, publish, byte-for-byte response, sitemap, withdrawal and deletion; browser sheet upload/publish/withdraw/delete; and horizontal document overflow on admin overview, content and public-sheet screens at widths 360, 390 and 768. That earlier test checked PDF delivery only; the newer public-learning test rendered a simple synthetic PDF in Chromium. This targeted test is not a full-site responsive, security or end-to-end certification. Existing production blockers, including safeguarding, independent security/privacy review, MFA and live service validation, remain in `PRODUCTION-READINESS-STATUS.md`.
